# Сеть дронопортов России

Индивидуальный исследовательский проект курса «Методы оптимизации».
Вариант — буква А: Псковская, Новгородская, Тверская области; допустимые первые буквы названий населённых пунктов: Ю, Я, А, Б, В.

## Структура
- `scripts/fetch_settlements.py` — загрузка кандидатов из Wikidata (SPARQL) в `data/raw/*.csv` + provenance json.
- `scripts/build_dataset.py` — воспроизводимый отбор основного (30–80) и малого (8–12) наборов точек в `data/processed/`.
- `scripts/check_variant.py [csv]` — проверка числа точек и связности графа перелётов ≤ 200 км.
- `scripts/build_demand.py` — гравитационный спрос на 3 года (заморожен до оптимизации).
- `scripts/evaluator.py` — быстрый эвристический оценщик плана: BFS-маршруты с пересадками, пулы мест по участкам, лимиты флота/слотов, накопленный бюджет по годам.
- `scripts/solve_milp_small.py` — точная MILP (PuLP/CBC) на малой instance.
- `scripts/solve_greedy.py [main|small]` — жадная базовая стратегия (прирост поездок на рубль).
- `scripts/solve_sa.py [main|small]` — имитация отжига (10 seed), старт из жадного решения.
- `scripts/compare_small.py` — сравнение MILP/greedy/SA на малой instance.
- `scripts/build_schedule.py` — проверенное расписание типовых суток итогового года: поминутные маршруты дронов, подзарядка по остатку дальности, возврат в базу, лимиты слотов; спрос корректируется масштабом до выполнимого.

## Воспроизводимый отбор точек (зафиксирован до оптимизации)
Страты: (регион × первая буква названия), 15 ячеек. Из каждой страты берутся до 5 точек с наибольшим населением (пропуски населения — в конец страты, tie-break — имя по возрастанию). Итог — основная instance (~75 точек).
Малая instance: 12 точек основной выборки с наибольшим населением, если их граф ≤ 200 км связен; иначе BFS-окрестность из 12 точек вокруг наиболее центрального узла основной выборки.

## Данные и допущения
- Населённые пункты: Wikidata (лицензия CC0), дата загрузки и текст запроса — в provenance json рядом с csv.
- Очистка: оставляем только объекты, у которых среди типов (P31) есть тип населённого пункта (город, село, деревня, посёлок, пгт, станция как НП, хутор); муниципальные образования (поселения, округа, районы, волости) и прочие объекты отбрасываются, чтобы не дублировать население входящих пунктов.
- Для фильтра по первой букве из названия убираются ведущие обозначения типа («городской округ», «муниципальный округ», «городское/сельское поселение»); исходное написание сохраняется в колонке `label` (пример: «городской округ Великие Луки» → «Великие Луки»).
- Пассажиропотоки: наблюдений нет → гравитационная модель; параметры спроса фиксируются до оптимизации.
- Технические и экономические параметры: учебные допущения с анализом чувствительности (курсовой справочник отсутствует).

## Паспорт параметров и спрос
- Параметры: `data/parameters.json` (v1, учебные допущения): дрон 10 мест, 120 км/ч, 5 мин оборот, 25 мин подзарядка, 250 млн ₽; дронопорт 60 млн ₽ (малый) / 120 млн ₽ (хаб при населении ≥ 20 тыс.), эксплуатация 10 млн ₽/год, 6 взлётов/час, 2/4 зарядных места; окно суток 07:00–21:00, 365 типовых суток, 50 тыс ₽/лётный час; бюджет 1 млрд ₽/год с переносом остатка.
- Спрос: `scripts/build_demand.py` строит гравитационную модель q_ij = K·P_i·P_j/(d_ij+d0)^γ·s(d) (γ=2, d0=10 км, модальный множитель s(d)=d²/(d²+20²) глушит поездки короче ~20 км как доминируемые наземным транспортом); K калибруется по норме 0.5 поездки/житель/год с ростом 1.00/1.15/1.32; округление целое с сохранением годового итога отправлений. Результат: `data/processed/demand_main.csv` + provenance json; спрос фиксируется до оптимизации.

## Запуск
```
uv sync
uv run python scripts/fetch_settlements.py
uv run python scripts/build_dataset.py
uv run python scripts/check_variant.py data/processed/points_main.csv
uv run python scripts/build_demand.py
```
