# Сеть пассажирских дронопортов России

Проект курса «Методы оптимизации». Вариант А: Псковская, Новгородская
и Тверская области; первые буквы названий Ю, Я, А, Б, В. Цель - больше

Поездка с пересадками учитывается один раз, по конечному прибытию.

## Быстрый старт

Нужны Python 3.11 и uv. Из корня проекта:

```powershell
uv sync --locked
uv run --locked python scripts/run_project.py check-data
uv run --locked python scripts/run_project.py all --profile bounded --max-wall-seconds 1800
```

Рекомендуемый ограниченный профиль использует готовые свидетельства,
ограничивает новые эксперименты 30 минутами и пересобирает документы.
Уже завершённые совместимые эксперименты повторно не запускаются.

`all` **без профиля** выполняет все расчёты, десять seed для основных конфигураций,
адаптивные запуски CBC, эксперименты и формирует отчёт. Это длительный
расчёт без общего лимита времени. Повторный запуск использует только
совпадающие входы, версию модели и настройки. Незавершённый SA продолжается
с последней сохранённой партии, включая состояние генератора.

Отдельные этапы:

```powershell
uv run --locked python scripts/run_project.py solve-small
uv run --locked python scripts/run_project.py solve-main
uv run --locked python scripts/run_project.py routing
uv run --locked python scripts/run_project.py planning
uv run --locked python scripts/run_project.py robustness
uv run --locked python scripts/run_project.py game
uv run --locked python scripts/run_project.py experiments
uv run --locked python scripts/run_project.py report
```

Для короткого ознакомительного запуска допустим `solve-main --seeds=0`.
`--seeds=` запускает только greedy/staged. Это не полный эксперимент.
`solve-small --non-adaptive-bound --limit 420` делает одну попытку CBC;
обычный режим увеличивает лимит на 420 секунд после каждой попытки.
Первоначальные попытки с удвоением сохранены как часть журнала.
Остановка - доказанный
оптимум релаксации или три улучшения сертифицированного разрыва подряд
менее 0,1 процентного пункта. Запросы `--no-resume` пересчитывают выбранную
стадию. Для полного комплекта нужны seed 0-9.

## Данные v1: воспроизведение без перезаписи

Ограниченный протокол завершения экспериментов (не более 30 минут новых
вычислений, без повторного CBC):

```powershell
uv run --locked python scripts/run_project.py all --profile bounded --max-wall-seconds 1800
```

Отдельные этапы того же протокола:

```powershell
uv run --locked python scripts/run_project.py experiments --profile bounded --max-wall-seconds 1800
uv run --locked python -c "from scripts.bounded import finalize_bounded; finalize_bounded()"
uv run --locked python scripts/run_project.py report --available-results --profile bounded
uv run --locked python scripts/run_project.py check-submission --available-results
```

Результаты записываются отдельно в `experiments_bounded.json` и `bounded/`.
Повторный запуск завершённого совместимого профиля использует результат.
Сравнивается сохранённый портфель; короткие поиски не подменяют полные
серии из десяти seed. Отсутствие решения в срок не означает невозможности
перевозок. Финальная проверка портфеля включается в общий лимит.

Зафиксированы `data/parameters.json`, `points_main.csv`, `points_small.csv`
и `demand_main.csv` в `data/processed/`: 75 и 12 пунктов. Их нельзя
перегенерировать после начала оптимизации. `check-data` воспроизводит отбор
и спрос в `output/repro-check/` и сравнивает с v1. Графы до 200 км имеют
одну компоненту; изолированных пунктов нет. Старые `build_dataset.py`
и `build_demand.py` теперь выполняют эту безопасную проверку.

Исходный снимок Wikidata от 12.10.2026 хранится в `data/raw/` вместе
с запросом и provenance. Очистка оставляет объекты с хотя бы одним типом
населённого пункта: город, село, деревня, посёлок, пгт, станция как НП,
хутор. Муниципальные образования и прочие объекты отбрасываются.
Префиксы типов удалены загрузчиком перед буквенным фильтром; исходная
метка сохраняется в `label`. `fetch_settlements.py` относится к первичной
загрузке, а не к запуску оптимизации; имеющийся снимок не перезаписывается.

Отбор буквально повторяет v1: до пяти пунктов на каждую из 15 страт
«регион × первая буква», по убыванию населения, затем имени; пропуски
населения в конце. Малый набор - 12 крупнейших пунктов основной выборки
(они связны). Неудобные точки и недостижимый спрос не удаляются.
Повторяющиеся названия различаются по `wikidata_id`.

Население исходного запроса - максимум опубликованных значений, который
может относиться к старому году. Точные совпадения утверждений P1082/P585
с замороженным значением записаны отдельно в `data/metadata/`; несколько
дат отмечаются как неоднозначные, отсутствующие - как недоступные.
Для обновления только этой метаинформации есть команда `metadata`.

Спрос синтетический, зафиксирован до оптимизации. Для отправителя i:

```text
w_ij = P_i*P_j/(d_ij+10)^2 * d_ij^2/(d_ij^2+20^2)
q*_ij,t = (0.5*P_i*g_t) * w_ij / sum_(k!=i) w_ik
g = (1.00, 1.15, 1.32)
```

Расстояние d - км, q - поездок/год. Население отправителя сокращается
при нормировании. Итог каждой строки равен округлённому `0.5*P_i*g_t`;
целые OD-количества получены методом наибольших остатков, стабильные
равные остатки разрешаются исходным порядком строк. Это исходящая
нормировка, а не единая константа K для всех отправителей. Суммы main
по годам: 267 450 / 307 571 / 353 032. Спрос small - сохранённые OD между
12 пунктами, без повторного нормирования. Экспериментальные наборы
и заново рассчитанный спрос хранятся отдельно в `experiments_v2/`.

## Операционная модель 2.1

Паспорт v1: 10 мест, 120 км/ч, 5 мин обслуживания, 25 мин зарядки,
200 км между зарядками, дрон 250 млн руб.; порт 60/120 млн руб. (хаб
от 20 тыс. жителей), содержание 10 млн руб./год, 6 взлётов/час,
2/4 зарядных места; 07:00-21:00, 50 тыс. руб./лётный час.

Все алгоритмы используют общий оценщик и независимый валидатор событий.
Остаток батареи переносится между участками. Дрон начинает и заканчивает
сутки на своей базе, обслуженным и полностью заряженным. База назначается
при покупке на весь горизонт; при отказе базы её дроны не летают.
Это консервативное допущение проекта. Посадки ограничены той же частотой,
что взлёты; лимит проверяется в скользящем часовом окне.

Год = семь шаблонов с весом 52 и дополнительный день с весом 1.
У пассажиров есть конкретные рейсы, общие места и минимум 5 мин на
пересадку. Взвешенные итоги ограничены годовым OD-спросом. Порожние
перегоны учитываются; отказ порта не возвращает вложения и не отменяет
его постоянное содержание. Ежегодные накопленные расходы проверяются
в рублях с точностью до копейки; остаток бюджета переносится.

CBC решает оптимистическую годовую релаксацию. Её incumbent не считается
выполнимым расписанием. Нижняя граница L - проверенный операционный план,
верхняя U - граница решателя; разрыв `100*(U-L)/U`. Для fixed timetable
целочисленное распределение пассажиров решает SciPy/HiGHS. Глобальная
оптимальность эвристических сетей не заявляется.

## Артефакты и защита

Актуальные расчёты: `data/results/model_v2/`; версия указана внутри JSON.
Каталоги конфигураций включают снимок задачи, стратегию, все 24 шаблона,
рейсы, зарядки, пассажирские пути, десять seed и контрольные точки.
В `published/` каждой конфигурации находятся итоговые планы после общей
очистки неиспользуемых вложений. Исходные результаты поиска сохраняются
в корне конфигурации. Очистка сохраняет пригодное расписание; стресс
может использовать его вместо менее успешной перестройки. Инвестиции
во время стресса уже фиксированы, возврата затрат нет.
Старые файлы непосредственно в `data/results/` - историческая агрегатная
модель v1; предварительные результаты 2.0 также не подменяют модель 2.1.

После `report`:

- `output/reports/report.md`, `output/pdf/report.pdf` - полный отчёт;
- `output/reports/management_memo.md`, `output/pdf/management_memo.pdf`;
- `data/results/model_v2/figures/` - карты и графики;
- `data/results/model_v2/plan/` - инвестиции и полные таблицы событий;
- `submission_manifest.json` - указатели и хеши комплекта.

Изменение параметров на защите, без правки v1:

```powershell
uv run --locked python scripts/run_project.py parameter-change --range-km 160
uv run --locked python scripts/run_project.py parameter-change --demand-multiplier 1.3
uv run --locked python scripts/run_project.py parameter-change --budget-multiplier 0.8
uv run --locked python scripts/run_project.py parameter-change --closed-port-id Q2235
```

Это перестройка эксплуатации при фиксированных вложениях, а не повторная
оптимизация инвестиций. Результат - `parameter_change.json` с признаками
выполнимости и разностью поездок. Сокращённый бюджет может сделать уже
выбранные вложения невозможными; такой результат не выдаётся за решение.

## Обязательные проверки

```powershell
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked python -m unittest discover -s tests
```

После формирования всех артефактов:
`uv run --locked python scripts/run_project.py check-submission`.
Проверка повторно восстанавливает конфигурации и сценарии, проверяет
десять seed, границу small, обязательные файлы и непустые страницы PDF.
Визуальный просмотр экспортированных страниц выполняется отдельно.

Зависимости устанавливаются только через uv в `.venv`. Добавлены
Ruff/mypy и stubs для проверок, ReportLab/pypdf для PDF; математический
стек сохранён. Импорт модулей не запускает расчёты и не записывает файлы.
Новые расчёты не требуют сети: запросы нужны только для первичной загрузки
и отдельного восстановления метаданных населения.
