# Согласованный план и проверяемые этапы

Этот документ описывает реализацию полного плана пользователя, а не
подменяет авторитетное задание PDF. Данные, территория и параметры v1
заморожены. Новые артефакты сохраняются в `data/results/model_v2/`.
Текущая операционная версия - 2.1; версия 2.0 является предварительной.

## Контракты и правила

- Обычные типизированные словари и функции; схемы - `model_types.py`.
- Instance: ID, координаты, население, OD, расстояния, параметры, хеши.
- Plan: год открытия по ID, накопленный флот и базы по годам.
- Result: события дронов, зарядки, пассажирские пути, деньги, проверки.
- Время - целые секунды, расстояние батареи - десятые доли километра;
  продолжительности округляются вверх, деньги - только при отображении.
- Год: семь дней с весом 52 и дополнительный с весом 1. OD-спрос
  ограничивается после взвешивания; всего 24 шаблона на горизонт.
- Дрон начинает и заканчивает сутки обслуженным, с полным зарядом
  на назначенной базе. База фиксируется при покупке на весь горизонт.
  Это исключает неучтённые межгодовые перемещения. При отказе базы
  дрон остаётся на земле. Эти допущения отдельно обозначены в отчёте.
- Остаток батареи переносится между рейсами; зарядка восстанавливает его.
  Обслуживание предшествует зарядке/следующему рейсу и задаёт пересадку.
- Инвестиции в начале года, инфраструктура и купленный флот сохраняются.
  Накопленные затраты <= накопленное финансирование. Отказы не дают
  возврата CAPEX и не уменьшают постоянный OPEX построенного порта.
- Лимит посадок принят равным лимиту взлётов, окно - скользящий час.
- Нижняя граница L - только проверенное расписание; верхняя U -
  корректная релаксация. Разрыв `100*(U-L)/U`, при U=L=0 - ноль.

## 1. Качество без изменения исходной математики

Устранить ошибки Ruff/format/mypy, убрать побочные эффекты импорта,
добавить аннотации, docstring и комментарии шагов. Старые функции
сохранить только как `legacy_*` для регрессии. Проверить прежние
main greedy 233 884 и SA seed 2 237 442 и неизменность входных хешей.

Артефакты: `legacy_baseline.json`, `output/analysis/checks_after_cleanup.json`.
Гейт: все проверки качества проходят, регрессионные числа совпадают.

## 2. Данные и происхождение

Проверить регионы, буквы, типы НП, ID, дубли, координаты, пропуски,
выбросы и связность. Воспроизвести отбор и origin-normalized спрос
во временный каталог и сравнить с v1. Сохранить изолированные узлы
и недостижимый спрос. Вернуть годы населения из совпадающих утверждений
в sidecar, неоднозначность не разрешать произвольно.

Модуль: `data_audit.py`; артефакты: `output/repro-check/`, `data/metadata/`.
Гейт: 75/12, одна компонента, ноль изолированных; точное воспроизведение,
источники и ограничения метаданных видны.

## 3. Общие идентификаторы и бухгалтерия

Хранить планы по ID, не разрешать одноимённые пункты произвольно.
Объединить CAPEX/OPEX, закупки, стоимость всех рейсов, ресурсы и перенос
бюджета. Исправить ошибку «в час/в минуту»: 6 взлётов/ч = 84/сутки =
30 660/год. Стоимость закрытого построенного порта сохраняется.

Модули: `model_data.py`, `evaluation.py`, `validation.py`.
Гейт: сериализация без потерь, бюджет без заимствования, фиксированные
расходы сохраняются при отказе.

## 4. Операционная выполнимость

Построить детерминированные задания дронов по спросу, включая перегоны,
зарядки, все доступные порты и без искусственного ограничения 24 участков.
Выбирать допустимые временные пути пассажиров, решать целое распределение
общих мест на конкретных рейсах через SciPy/HiGHS. Считать только конечное
прибытие. Независимо восстановить из JSON батарею, положение, интервалы,
зарядные места, движения, пассажиров, годовой спрос и деньги.

Модули: `operations.py`, `validation.py`. Круговые задания - эвристическое
ограничение качества, которое необходимо явно обсуждать в отчёте.
Гейт: любое нарушение явно перечисляется и исключает решение из рейтинга.

## 5. Сертификат малой задачи

MILP-релаксация включает открытие, флот, потоки OD, места, явные пустые
рейсы, балансы, накопленный бюджет и необходимые ресурсы времени/зарядки.
Не требовать зарядки после каждого рейса. При полном заряде на обеих
границах суток необходимы `distance <= range*charge_count` и ограничение
общего времени флота. Удаление порядка событий расширяет допустимость.

CBC: строго последовательный режим `threads=0` (режим `threads=1`
зависал в установленной сборке Windows); seed=1. Начальный лимит 420 с,
затем увеличение на 420 с (ранние удвоенные лимиты сохранены в логе).
Остановка: оптимум релаксации или три прироста разрыва
подряд менее 0,1 п.п. Сохранять LP, MPS, переменные incumbent, логи,
статус решения отдельно от статуса задачи, лимиты, время, L/U и разрыв.
Стратегии incumbent повторно оценивать через общий оценщик.

Модуль: `bounds.py`; `small_bound/`. Гейт: проверенный L и полезный U,
причём агрегатная цель не используется как допустимый L.

## 6. Greedy и собственный SA

Greedy начинается с выполнимой связной пары и проверяет прирост поездок
на дополнительные расходы, включая совместное открытие и покупку.
Скрининг top-12 движений является эвристикой, а не доказательством
глобально лучшего шага. SA стартует из лучших greedy/staged; меняет годы,
состав сети, флот и базирование. Сначала дешёвая проверка инвестиций.

Seed 0-9; температура 1% стартовой цели, множитель 0,995 на предложение,
нижний порог 0,001 начальной температуры; партии 800 предложений,
три партии без лексикографического улучшения. Критерий: поездки,
затем меньшие расходы. Кэш зависит от входов, стратегии, сценария
и версии. Состояние RNG и лучшая сеть сохраняются атомарно.

Модули: `search.py`, `studies.py`; `configurations/*/`.
Гейт: десять воспроизводимых результатов со всеми расписаниями и временем.

Общая финальная обработка всех номинальных методов удаляет порты без
рейсов, зарядки и базирования. Сохранённый график остаётся допустимой
альтернативой новой конструкции; выбирается лучший. Исходные поисковые
файлы сохраняются, обработанные планы лежат в `published/`.

## 7. Два алгоритмических сравнения

BFS/A*: все достижимые OD одного графа, один запрос и все назначения;
одинаковые веса времени/стоимости, Dijkstra как эталон. Эвристика A*
использует неокруглённую географию с вычетом возможной ошибки округления.
Публиковать пересадки, время, стоимость, раскрытия и runtime. Статическое
время отделить от ожидания расписания.

Staged оптимизирует только текущий год и фиксирует введённые решения;
будущие обязательные расходы резервируются. Joint использует весь
горизонт и включает staged в старт. Разности эвристик не являются
теоремой о превосходстве подхода.

Модули: `routing.py`, `commands.compare_planning`; JSON сравнений.
Гейт: одинаковые данные, бухгалтерия и валидатор; A* совпадает с Dijkstra.

## 8. Устойчивость и игра

Сценарии: база, спрос ×0,7/×1,3 и дальность 160 км на все годы; отказ
каждого допустимого порта на весь год 3. Вложения/флот/базы фиксированы,
маршруты и расписания перестраиваются. Оптимизировать max-min на том же
явном множестве, сравнить потери базы, выигрыш худшего случая, расходы,
опасный отказ и годовые эффекты.
Пригодный исходный график сохраняется среди вариантов ответа; изменённый
спрос перераспределяется целочисленно. При отказах построенные порты
не удаляются из инвестиционного плана и не дают возврата затрат.

Игра small: проверенные сети greedy/SA/MILP-derived; соперник закрывает
построенный порт в году 3. Один раз построить матрицу payoff, отдельно
измерить preprocessing. Перебор и alpha-beta используют одну матрицу;
сравнить значение, узлы, листья и время обхода.

Модуль: `studies.py`; `robustness.json`, планы и худшие расписания,
`game.json`. Гейт: инвестиции не возвращаются, игровые значения совпадают.

## 9. Эксперименты

- Масштаб 12/25/50/75: детерминированные крупнейшие пункты, сохранённые
  OD, изменение знаменателя спроса явно указано.
- Транш ×0,5..×2 с шагом 0,25; два midpoint уточнения наибольшего
  прироста на рубль.
- Пропуски: drop и медиана группы типа НП, отдельные наборы и спрос;
  сравнение выбранных ID, сетей и целевых.
- Случайность: десять seed каждой основной конфигурации, парные числа,
  среднее, sd, медиана, диапазон, runtime, распределения прироста.
  Bootstrap среднего прироста seed=0 ограничен данным экземпляром;
  sign test SA против сохраняемого старта не применять.
- Учебные цены дрона/порта, OPEX, цена лётного часа, скорость, зарядка
  ±20%; соседние целые мощности движений и зарядных мест. Для этой
  вспомогательной чувствительности используется seed 0.

Готовые идентичные конфигурации переиспользуются. Модуль: `studies.py`;
`experiments.json`, отдельные входы, полный снимок каждой задачи.
Гейт: все основные конфигурации имеют десять seed и проверенные сети.

Восемь элементов: русский отчёт Markdown/PDF, пакет данных и provenance,

В отчёте: постановка, допущения, модель, методы, числа, ограничения,

Модуль: `reporting.py`; `output/reports/`, `output/pdf/`, `figures/`,
`plan/`, `submission_manifest.json`. PDF визуально проверить постранично.
Команда `parameter-change` обеспечивает изменение допущений на защите
без изменения v1. Команда `all` воспроизводит полный процесс.

## Обязательная проверка готовности

```text
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked python -m unittest discover -s tests
```

Сфокусированные unittest проверяют ID/сериализацию, батарею и заряд,
непрерывность/базирование/пересадки, места/зарядные слоты/часовые движения,
асимметричный спрос и пустые рейсы, бюджет/перенос/отказы, веса суток,
границы/статусы/таймаут CBC. Реальные сравнения дополнительно утверждают
равенство A*/Dijkstra и перебора/alpha-beta.

После каждого математического этапа: малая задача, сохранённые метрики
и неизменные четыре хеша. Готово только после прохождения качества,
операционной проверки, сертификата small, согласованности чисел,
полного комплекта и проверенного возобновления. Минимальная целевая
и глобальная оптимальность main не обещаются.

## Ограниченный протокол завершения (01.11.2026)

Для новых экспериментов согласован общий предел 1800 секунд. Существующие
сертификат CBC, решения и десять запусков основной задачи сохраняются.
Портфель проверенных сетей сравнивается на семи бюджетных точках и двух
адаптивных уточнениях. Для недостающих точек допускаются seed 0/1/2
по 60 секунд, для недостающей чувствительности — seed 0 до 45 секунд.
Супервизор останавливает принадлежащие ему процессы; незавершённое решение
не становится результатом. Фоновых неограниченных повторов нет.

Эквивалентность двух стратегий обработки пропусков проверяется по полным
выбранным данным и спросу. При совпадении повторная оптимизация исключается.
Успех сокращённого протокола означает девять проверенных бюджетных точек,
доказанное сравнение качества данных и результат либо явный статус
отсутствия найденного расписания для каждого из 16 случаев чувствительности.
Он не означает завершение первоначальных десяти seed на каждой новой
конфигурации. Источники, ограничения, время и отдельная проверка сохраняются
в ограниченном профиле, итог — `completion_bounded.json`.
