# Планирование сети пассажирских дронопортов

Учебное исследование по дисциплине «Методы оптимизации». Вариант А.

## Введение

В работе рассматривается задача развития пассажирской сети дронопортов на три года. Необходимо определить, где и когда открывать порты, сколько дронов покупать и как организовать перевозки в пределах выделенного бюджета. Качество плана оценивается по числу завершённых пассажирских поездок. Поэтому недостаточно выбрать выгодные направления на карте: для них должно существовать выполнимое расписание.

Лучший найденный план обеспечивает 250 647 поездок за три года при затратах 2,844 млрд руб. Он обслуживает 27,01% расчётного спроса. К концу третьего года число портов достигает 11, численность флота — 3. Ниже приведены исходные допущения, методы поиска и проверки, позволяющие оценить этот результат и границы его применимости.

## 1 Исходные данные и границы задачи

По условиям варианта сеть размещается в Псковской, Новгородской и Тверской областях. Допустимы населённые пункты, названия которых начинаются с букв Ю, Я, А, Б или В. Это правило распространяется и на пересадочные узлы [1].

Сведения о населённых пунктах получены из Wikidata; в работе используется снимок данных от 12 октября 2026 года [2]. Из 3 977 исходных объектов выделены 2 512 кандидатов, относящихся к населённым пунктам. У восьми кандидатов отсутствует численность населения. Для каждой комбинации области и начальной буквы отбираются пять наиболее населённых пунктов. Так получен основной набор из 75 пунктов. Малая задача содержит 12 крупнейших пунктов.

Проверка данных включает идентификаторы, координаты, пропуски, повторяющиеся названия и связность графа. В обоих наборах все пункты связаны цепочками перелётов длиной не более 200 км. Пункты с одинаковыми названиями учитываются раздельно: например, в основном наборе есть три Юрино. Различить их позволяют идентификаторы Wikidata.

У данных о населении есть существенное ограничение. Исходный запрос возвращает максимальное из опубликованных значений, которое не обязательно является последним по времени. Для 73 выбранных пунктов удалось однозначно установить дату соответствующего наблюдения; для двух дата неоднозначна. Крупные значения населения сохранены: их удаление как статистических выбросов изменило бы смысл транспортной задачи.

Исходные значения после начала оптимизации не менялись. Снимок данных, правила отбора и контрольные суммы входят в комплект проекта. Проверка воспроизводимости повторяет преобразования в отдельном каталоге и не перезаписывает исходные файлы.

## 2 Спрос и параметры перевозок

Наблюдений реальных пассажиропотоков нет, поэтому спрос задаётся расчётной моделью. В первом году из каждого пункта отправляется в среднем 0,5 поездки на жителя. Для второго и третьего годов используются коэффициенты роста 1,15 и 1,32. Объём распределяется между направлениями с учётом населения пункта назначения и расстояния:

w(i,j) = P(j) · s(d) / (d + 10)², где s(d) = d² / (d² + 20²).

Здесь P(j) — население пункта назначения, d — расстояние в километрах. Веса нормируются отдельно для каждого пункта отправления. После округления годовой суммы поездки распределяются методом наибольших остатков. Спрос направленный: объёмы в противоположных направлениях могут различаться. Эти оценки нужны для сравнения планов в одинаковых условиях и не заменяют прогноз реального спроса.

В модели дрон вмещает десять пассажиров, летит со скоростью 120 км/ч и может пройти до 200 км между зарядками. Обслуживание после перелёта занимает пять минут, полная зарядка — 25 минут. Перевозки выполняются с 07:00 до 21:00 ежедневно. В зависимости от типа порта предусмотрены два или четыре зарядных места; допустимая интенсивность составляет шесть взлётов в час. Такой же предел принят для посадок.

Стоимость дрона составляет 250 млн руб., строительства порта — 60 или 120 млн руб., его содержания — 10 млн руб. в год. Час полёта оценивается в 50 тыс. руб. В стоимость строительства включена зарядная инфраструктура, а в часовую ставку — энергия, персонал и обслуживание дронов. Постоянные расходы порта учитываются отдельно. Параметры зафиксированы в паспорте модели [3]; часть из них представляет учебные допущения.

Финансирование поступает равными траншами по 1 млрд руб. в начале каждого года. Неиспользованные средства переносятся на следующий год. Заимствования и дополнительное финансирование за счёт выручки не предусмотрены.

## 3 Постановка модели

Стратегические решения определяют год открытия каждого порта, покупки дронов и их базы. Открытые порты сохраняются в сети, а приобретённый флот не сокращается. База назначается дрону при покупке и остаётся постоянной. При этом он может выполнять рейсы и заряжаться в других открытых портах.

Целевая функция равна сумме завершённых поездок по всем направлениям и годам:

F = Σ(t) Σ(o,d) S(o,d,t) → max.

Здесь S(o,d,t) — число пассажиров, доставленных из o в d в году t. Одна поездка с пересадкой учитывается один раз, по прибытии в конечный пункт. При одинаковом числе поездок предпочтение получает план с меньшими расходами.

Основные обозначения приведены в таблице 1.

Таблица 1 — Обозначения модели

| Обозначение | Смысл |
| --- | --- |
| x(i,t) | Открыт ли порт i в году t |
| N(t) | Число приобретённых дронов к году t |
| Q(o,d,t) | Годовой спрос между пунктами o и d |
| S(o,d,t) | Завершённые поездки между этими пунктами |
| C(t) | Расходы в году t |
| z(k,p) | Пассажиры на допустимом временном пути p в шаблоне суток k |
| w(k) | Число дней, представленных шаблоном k |

Для каждого направления выполняется 0 ≤ S(o,d,t) ≤ Q(o,d,t). Пассажир может пересаживаться, если следующий рейс отправляется не раньше чем через пять минут после прибытия предыдущего. Суммарная загрузка каждого рейса не превышает десяти человек. Для заданного расписания числа z(k,p) выбираются целочисленными; годовой объём получается суммированием по путям и шаблонам с весами w(k).

Движение дрона проверяется последовательно. После каждого перелёта запас хода уменьшается на длину участка, а зарядка восстанавливает его до 200 км. Заряжаться после каждого рейса не требуется. При проверке учитываются положение дрона, время обслуживания, занятость зарядных мест и число движений в каждом скользящем часовом интервале. В начале и конце суток дрон находится на своей базе с полным зарядом. Это консервативное допущение позволяет повторять суточный график без скрытых перегонов или зарядок за пределами рабочего окна.

Один год представлен семью шаблонами суток с весом 52 и ещё одним днём с весом 1. Сумма весов равна 365. Порты, флот и базы общие для всех шаблонов данного года, а ограничения спроса применяются к их взвешенной сумме. Такой подход позволяет учитывать редкие поездки без требования выполнять каждое направление ежедневно.

Бюджет ограничивается накопленной суммой финансирования:

Σ(y ≤ t) C(y) ≤ t · 1 млрд руб., t = 1, 2, 3.

В C(t) входят строительство новых портов, покупка дронов, ежегодное содержание всех открытых портов и стоимость всех перелётов, включая порожние. Полётные расходы рассчитываются по расстоянию и скорости без промежуточного округления часов. Бюджет дополнительно проверяется с точностью до копейки.

## 4 Методы поиска и проверка решений

В качестве исходного решения используется жадный алгоритм. Он сравнивает открытия портов, покупки дронов и совместные инвестиции по приросту поездок на рубль дополнительных затрат. Совместные изменения важны: новый порт может начать приносить пользу только после покупки ещё одного дрона. На каждом шаге подробно оцениваются 12 перспективных изменений, поэтому алгоритм служит практической базовой стратегией, а не гарантией лучшего возможного жадного шага.

Для улучшения решения применяется имитация отжига. Поиск меняет состав сети, годы открытия, покупки и базирование вновь приобретаемых дронов. Начальными решениями служат проверенные жадный и поэтапный планы. Начальная температура составляет 1% числа поездок стартового решения и уменьшается в 0,995 раза после каждого предложения; нижний предел — 0,001 начальной температуры. Запуск завершается после трёх последовательных серий по 800 предложений без улучшения. Для основной задачи выполнены десять запусков с фиксированными значениями seed от 0 до 9.

Каждый инвестиционный план оценивается через расписание. Сначала строятся задания дронов с возвратом на базу, зарядками и необходимыми порожними перелётами. Затем целочисленная модель HiGHS распределяет пассажиров по допустимым временным путям. Одинаковые правила оценки используются для всех методов.

Независимая проверка повторно восстанавливает движение дронов и пассажиров по сохранённым событиям. Она проверяет батарею, непрерывность маршрута, зарядки, пересадки, вместимость, годовой спрос и бюджет. План с нарушениями не участвует в сравнении допустимых решений. Если порт вообще не используется для рейсов, зарядок или базирования, он исключается из первоначального инвестиционного плана. При стресс-тестах инвестиции уже зафиксированы и такой пересмотр не допускается.

Для малой задачи дополнительно построена оптимистическая смешанно-целочисленная модель, решаемая CBC. Она сохраняет необходимые ограничения спроса, мест, балансов рейсов, расходов и ресурсов, но не задаёт подробный порядок всех событий. Поэтому любой допустимый план с расписанием входит в её множество решений. Полученная верхняя граница показывает, сколько поездок теоретически ещё может отделять найденный план от оптимума.

Проверенное расписание даёт нижнюю границу L = 216 335, а завершённые расчёты CBC — верхнюю U = 242 700,11. Сертифицированный разрыв равен 100 · (U − L) / U = 10,86%. Поиск остановлен до выполнения критерия сходимости; оптимальность не доказана. Найденное CBC агрегатное решение само по себе не считается выполнимым расписанием. Подробности попыток приведены в приложении А.

## 6 Сравнение маршрутизации и способов планирования

Для поиска пассажирских маршрутов сопоставлены поиск в ширину (BFS) и A*. BFS находит путь с наименьшим числом перелётов. A* ищет путь с наименьшим временем или стоимостью, используя географическую оценку оставшегося пути. Поправка на округление расстояний сохраняет допустимость этой оценки. Результаты A* проверены по алгоритму Дейкстры.

Сравнение проведено для 110 направленных пар на сети открытых портов. Рассмотрены как отдельные запросы, так и поиск всех назначений для одного отправителя. Во втором случае BFS обходит граф один раз, тогда как A* запускается для каждой цели. Поэтому число раскрытых вершин само по себе не определяет общее время работы.

Таблица 4 — Поиск маршрутов в статическом графе

| Работа | Время, с | Раскрытия |
| --- | --- | --- |
| BFS запросы | 0,000499 | 715 |
| BFS все цели | 0,000120 | 121 |
| A* время, все запросы | 0,003295 | 301 |
| A* стоимость, все запросы | 0,003115 | 272 |

В этом сравнении учитываются длительность и стоимость участков, но не ожидание рейсов. Путь в статическом графе показывает возможность связи между портами; наличие подходящего отправления и свободного места проверяется уже по расписанию.

Для инвестиционного планирования сравниваются два подхода. Поэтапный алгоритм улучшает только текущий год, сохраняя уже принятые решения и резервируя обязательные будущие расходы. Совместный поиск оценивает весь трёхлетний горизонт и использует поэтапный план как один из стартов.

Таблица 5 — Поэтапное и совместное планирование

| Подход | Поездки по годам 1/2/3 | Всего |
| --- | --- | --- |
| Поэтапный жадный | 45 419 / 78 027 / 104 921 | 228 367 |
| Совместный жадный | 41 311 / 78 027 / 104 921 | 224 259 |
| Совместный отжиг | 45 419 / 84 872 / 120 356 | 250 647 |

Лучшее совместное решение перевозит на 22 280 пассажиров больше поэтапного. Однако совместный жадный алгоритм уступает поэтапному. Следовательно, полученные различия характеризуют конкретные эвристики: их нельзя считать доказательством общего преимущества любого совместного алгоритма.

## 7 Устойчивость сети и игровой выбор

Для базового плана проверены изменение спроса на ±30%, снижение дальности до 160 км и закрытие каждого допустимого порта на весь третий год. Порты и приобретённый флот при этом сохраняются в инвестиционном плане. Строительные затраты не возвращаются, а постоянное содержание продолжается. Перестраиваются только расписания и пассажирские маршруты; при отказе базы закреплённые за ней дроны остаются на земле.

Наиболее опасен отказ порта Великий Новгород. В худшем из проверенных сценариев базовый план обеспечивает 170 960 поездок за три года. Робастная альтернатива, ориентированная на худший сценарий, повышает этот результат до 185 739. Цена такой защиты — потеря 16 039 поездок в обычных условиях и увеличение затрат на 151,97 млн руб.

На малом наборе также рассмотрена игра с конечным числом действий. Сначала выбирается одна из сетей, полученных жадным алгоритмом, имитацией отжига или на основе MILP. ## 9 Ограничения исследования

Основное ограничение связано с данными: спрос синтетический, а население не во всех случаях относится к однозначно установленному году. Поэтому найденные объёмы следует понимать как результаты учебной модели. Перед практическим применением необходимы наблюдения реальных потоков, актуальные цены и проверка эксплуатационных условий.

Качество решения ограничено и способом поиска. Отбор перспективных изменений и построение круговых заданий сокращают объём вычислений, но могут пропускать более выгодные планы. Для основной задачи глобальная оптимальность не доказана. На малом наборе качество ограничено сертифицированным разрывом 10,86%.

Консервативные условия повторяемости суток и постоянного базирования также влияют на перевозки. Они делают расписания непосредственно проверяемыми, однако не охватывают возможные ночные перегоны или платное изменение базы между годами. Выводы об устойчивости относятся только к рассмотренному набору сценариев.

## Заключение

Получен трёхлетний план, который обеспечивает 250 647 завершённых поездок при расходах 2,844 млрд руб. Он учитывает не только строительство и покупки, но и фактическую работу дронов: остаток заряда между рейсами, обслуживание, пересадки, порожние перелёты и ограничения портов. Расписания выполнимы для всех шаблонов каждого года.

Имитация отжига улучшила жадную стратегию на 26 388 поездок. При этом зависимость от начального решения и случайного поиска сохраняется, поэтому сравнение основано на десяти запусках и не трактуется как доказательство оптимальности. Наиболее существенная эксплуатационная зависимость связана с портом Великий Новгород; робастная сеть позволяет уменьшить потери при его отказе ценой снижения обычной перевозки.

Результат можно использовать как воспроизводимый пример совместного инвестиционного и операционного планирования. Следующий этап исследования — завершение экспериментальной сетки и уточнение исходного спроса; переход к реальному проекту требует самостоятельной проверки экономических и эксплуатационных предпосылок.

## Приложение В. Воспроизведение

Для подготовки окружения используется команда `uv sync --locked`. Сборка документов из сохранённых расчётов выполняется командой `uv run --locked python scripts/run_project.py report --available-results`, проверка комплекта — `uv run --locked python scripts/run_project.py check-submission --available-results`.

Команда `uv run --locked python scripts/run_project.py all` запускает полный вычислительный цикл, включая оставшиеся эксперименты. Повторный запуск использует только результаты с совпадающими входами, параметрами и версией модели. Проверки кода включают Ruff, форматирование, mypy и unittest. Неизменность исходных данных контролируется по SHA-256.
